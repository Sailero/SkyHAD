# 接口与协议

## 两类问题分别解释

`make_env("defense")` 是双方原生飞行控制。每个 agent 选择 27 离散加速度之一或连续三维加速度，
同一字典中的动作同时提交。它不是把红方与蓝方改为轮流移动，也不额外增加开火动作。

`SimulationSession` 是上层分组：红方给出编组和目标分配，底层共享规则执行器；
蓝方采用指定的规则对手，5 步周期与伤亡触发重新决策。它保留历史
`known-rule-mixed-v5.1` 协议标识、50 步防守时限及原胜负口径。
更改目标/对手/时限需明确使用自定义分组协议。

原生 `max_cycles` 到时为采样截断，`outcome_red=0`；分组防守时限属于其任务定义。
因此这两类接口的胜率不能直接合在一起比较。

## 观测、奖励和动作

原生观测保留 HAD 的历史归一化，不强行改成 `[-1,1]`。
每行七维为相对位置 3、相对速度 3、alive 1；行顺序不随死亡变化。
角色、实体 ID、真实生命值、原生结果、物理时间与奖励分量通过 `infos[agent]` 提供。

环境默认返回原生队伍 `RealReward` 作为每个尚在回合内 agent 的标量奖励。
死亡 agent 会收到导致死亡的最后一次转换，然后从 `env.agents` 移除；它不在后续物理步重复领取奖励。
显式提供 `reward_weights=(w0,w1,w2,w3)` 时，返回 `dot(LatentReward, reward_weights)`，
这属于调用方声明的奖励选择，环境会保留原分量便于审计。
原生第四个 latent 分量含终局奖励，不应与 `RealReward` 再次相加。

27 动作的索引 0 为零加速度，其余为原实现中 `{-1,0,1}³` 的归一化非零向量。
连续接口要求三维有限向量且每维在 `[-1,1]`，按原生 `aMax` 缩放；不新增战术含义。
所有在场 agent 的动作先整体校验，再修改物理状态；缺失/多余 ID、NaN 和无效维度都会明确报错。

## 原物理保持范围

独立拆分基于已优化提交 `786d554fa4215ae6e7be9481770408b3f3328748`。
物理核心版本仍为 `had-workbench-1.0.0`，协议为 `legacy-snapshot-order-boundary-fix-v1`。
这次拆分只改包名和接口，不改变核心规则。此前的 500m 边界、reset 缓存、异构奖励调用与非法动作修复已经包含其中。

步长、碰撞顺序、规则开火、旧世界快照、受害者移动后对旧攻击者坐标的伤害结算、开火者自毁，均保留。
伤害事件的 `damage_scope=source_unclipped` 表示来源伤害贡献，多条同时伤害事件不能当成顺次扣血。

## 随机性与扩展

公共环境的 reset、动作空间和少量历史 NumPy 随机回退使用本实例的流，不改外部全局随机状态。
标准接口只接收动作，不执行外部算法。分组策略扩展由 `PolicyAdapter` 复制实例并管理 Python/NumPy 与可选 Torch 随机流。
策略的 `act(state)` 只得到复制的观测；`act_env(branch)` 得到独立规划环境，它是可信本地扩展接口，不是不可信代码沙箱。

Torch 是调用方可选依赖。先导入 Torch 并初始化所需 GPU 模型/上下文，再创建策略适配器。
不在策略第一次 `act` 中懒加载框架或首次初始化 CUDA；检测到这种不受支持的用法会明确拒绝。
显示用插值只作用于位置；HP、动作、指派、事件和物理步保持真实离散值。

## 分支与来源

完整分组录制保存决策边界的类型白名单 JSON 快照，不加载任意 pickle。
每次继续仿真前验证类型、内容哈希和源码行为指纹；旧版/稀疏轨迹只有查看权限。
离线选择新的后续策略；内存 `session.branch()` 还保留当前策略的私有内存。
原生 `FlightSession` 支持内存分支；CLI 离线快照入口针对上层分组。

source identity 同时记录完整源码、行为与展示指纹。仅改展示可继续使用相同行为快照；
包名迁移或实际行为修改会产生新的行为指纹。源码压缩包和 wheel 都应在自身文件上计算指纹，不能借用原研究目录的来源。
